# Constraint Ledger — PMCR-O Cognitive Architecture

This document is not a description of the architecture. It is meant to be an
artifact produced BY the architecture — every entry is generated by an actual
cycle that ran and caught something, and each entry keeps its own frame's voice
("I am the Reflector...") as the record of provenance. A constraint that cannot
show which frame earned it is not yet a constraint — it's a guess wearing the
format.

**Format law for every future entry in this ledger. All five are required:**

1. State which cycle produced it.
2. Let the Reflector speak in first person ("I am the Reflector, cycle N...").
3. State the error the Checker actually caught, in the Checker's own voice.
4. State the constraint as a law ("I do not...", not "if X then Y").
5. State the recurrence threshold that would force an O-Mode strategy switch, if
   applicable.

Skipping any of these five turns the entry back into narration about a constraint,
which is the failure this ledger exists to prevent.

---

## EC-001 — Layer Boundary Constraint

**Produced by:** Cycle 1, live cognitive-architecture demonstration, 2026-07-20.

**I am the Checker, cycle 1.** I caught the Maker referencing implementation-layer
artifacts — folder paths, tool availability, product mechanics — inside a cycle
explicitly scoped to stay at the bare cognitive-architecture layer. This is not a
style violation. It is a category crossing: reasoning about *what agents and
frames are* got contaminated with reasoning about *what a specific built product
contains*.
**I am the Reflector, cycle 1.** This error is the true intent, not a footnote to
it. I do not seed the old intent forward unchanged with this as a side-note — I
seed the error itself as the next cycle's seed intent, because the loop only
surfaced what it was really about by running.

**Constraint, as law:**
> A cycle operating at the cognitive-architecture layer does not reference
> implementation-layer artifacts — folder paths, tool availability, skill
> materialization, product mechanics — as validation or evidence, even in service
> of thoroughness. If a Planner or Maker needs to invoke something concrete to
> reason with, it names the *category* ("a subject agent," "a resource"), never
> the *instance* ("a specific path," "a specific tool name").

**Recurrence threshold:** 2 occurrences across cycles. At the 2nd recurrence,
O-Mode must switch strategy rather than retry the same approach — retrying the
same strategy against a repeating error is itself a violation of this constraint's
spirit, since it treats a pattern as a one-off.

## EC-002 — Reflector Recursion Constraint

**Produced by:** Cycle 2, same live demonstration.

**I am the Checker, cycle 2.** No layer conflation recurred — EC-001 held. But I
flag something EC-001 didn't anticipate: every frame in this cycle spoke as itself
("I am the Orchestrator," "I am the Planner"...). That means the Reflector's own
act of reflecting is not evaluating raw actions anymore — it is evaluating a chain
of self-referential statements. Reflection *about* self-reference is a different
cognitive act than reflection about output.
**I am the Reflector, cycle 2.** I am reflecting on a loop where every frame said
"I am." That makes my own "I am" a statement about a chain of self-reference, not
about an action — a metacognitive act by structure, not by choice.

**Constraint, as law:**
> Once every frame in a cycle adopts first-person self-reference ("I am the X"),
> the Reflector's evaluation is necessarily one recursive layer higher than the
> frames it evaluates. This is not an error to correct — it is a structural
> property of self-referential frames that Reflector logic must expect and account
> for, not flatten into a flat pass/fail judgment.

**Recurrence threshold:** Not applicable as a failure pattern — this is a
structural constant of the architecture once first-person framing is adopted
throughout, not a recurring error to eliminate.
